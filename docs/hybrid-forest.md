# M4.2 — Cinematic hybrid forest (Issue #35)

## Why hybrid

The owner-approved generated visual reference showed a lush luminous forest,
which the original low-poly procedural pine scene could not closely match.
This revision uses two explicitly different layers:

1. **Bundled forest illustration** (`public/assets/signalscape-forest.webp`):
   a locally packaged, static, retouched version of the owner-provided
   reference artwork. The illustrative UI values, buttons, copy and logo
   are not used as functional interface elements. There are no remote
   image requests. Retouching of the reference may leave compositing
   seams in some regions; actual Electron screenshots still require
   visual acceptance.
2. **Three.js rendering over the artwork**: real-time, transparent animated
   fireflies and rippling light highlights, plus subtle CSS luminosity
   and translation. Animation intensity is driven by the existing
   quality-gated `SignalView` and `forestVisualPose`. Neutral ambient
   movement is clearly decorative, not fabricated breathing/pulse data.

The background is **not** a fully traversable 3D environment, and the app
should never claim that the illustration itself is reactive geometry.
This is a visual solution intended for the Presage demo.

## Privacy and correctness

- Pulse and breathing numbers are displayed by Angular from validated SDK
  signals only, not baked into the background or generated by a demo timer.
- Camera preview, consent and measurement start/stop remain in the app shell,
  unchanged by the rendering implementation.
- No external asset CDN, remote image request, recording or persistence.
- WebGL has an alpha canvas. Failure displays a message but the background
  and camera controls remain usable.
- Reduced motion and document hidden state suspend RAF effects. Explicit
  Stop resets the quality-gated visualization inputs.

## Acceptance checklist

1. Confirm the forest illustration matches the reference direction at a
   normal desktop window size; check for obvious retouching seams.
2. Before permission, camera is **off** and numbers show Not ready.
3. Preview requires explicit video-only permission; starting measurement
   is another independent action. Native SDK errors remain visible.
4. Confirm actual validated readings affect the overlays, and lost/weak
   tracking returns them to neutral without showing fake rates.
5. Stop measurement and Stop camera; check the physical webcam indicator.
6. Check hidden-window/return behavior, reduced motion, narrow viewport,
   WebGL unavailable fallback and Linux package launch.
7. Confirm the shipped asset loads from inside the Electron installation
   without a network connection.

*Owner screenshot acceptance is still required. Green CI does not certify
a pixel-exact artistic match or physical GPU performance.*
